# V2.3.2

- discord.js housekeeping: every interaction response now passes `flags: MessageFlags.Ephemeral` instead of the deprecated `ephemeral: true` option (all ten call sites in the bot — deferrals, error replies, `/site info`, and the failure-button flow), silencing the startup-log deprecation warning discord.js 14.27 emits on each ephemeral reply. Behavior is unchanged; the flag is the same ephemerality, spelled the way discord.js now requires.

- A finished agent turn is never thrown away anymore: its summary is always displayed, its work is committed whenever git accepts it, and the errors arrive in a follow-up message. Previously any failure after the prompt — validation that still failed after the repair round-trip, a commit/push error, a publish error — failed the whole turn: the agent's summary was discarded, nothing was committed, and the thread saw only `❌ … failed · reference ERR-…`. `completeTurn` is now failure-tolerant past the prompt. A validation failure (including structural ones like a missing `index.html`, and a repair round-trip that itself cannot run because the agent service errored — the original validation errors and the original summary are kept) commits the work with a `— failed validation, not published` commit subject but never publishes, so the live site keeps the last validated version and the next reply fixes from the committed state. A publish failure after a validated commit keeps the clean subject — that version is good and one `/site republish` away from live. A commit failure leaves the finished edits preserved uncommitted in the workspace. In every case the turn's status message still shows the agent's summary, with an outcome-specific header (`⚠️ … validation failed — committed, not published` / `… publishing failed — not live` / `… committing failed · edits preserved`) and the usage subtext, and a separate follow-up thread message carries the actual errors: validation errors verbatim, delivery errors with an incident reference — commit/publish failures still page the private error-report DM through the same incident pipeline as before. AI title adoption is skipped for turns that don't ship (failed builds keep their slug name), `/site revert` still works on committed-but-unpublished turns (`lastCommit` tracks them, so a revert undoes the failed commit and republishes the previous validated version), and the public gallery refresh is now best-effort — a stale index can no longer fail an already-published turn. The AGENTS.md end-of-turn contract tells the agent that still-failing validation commits unpublished and the next reply must fix it.

- Failed turns are now ledgered in the usage log. Previously only completed turns reached `USAGE_LOG_FILE` — a failed run's tokens were spent but invisible to `/site-admin usage` and `/site info` (recorded in V2.3.1 as a caveat). The agent harness now attaches the usage it had observed from the event stream to any prompt error it throws, and `mutate()`/`recoverTurn()` ledger exactly once per outcome: returned turns record after `completeTurn`, marked `failed` when validation or delivery failed or the commit never happened; thrown failures record the partial usage — the turn's hoisted total plus whatever the failing prompt attached to the error — or a zero-token entry when nothing was observable, so day turn counts stay truthful. Ledger entries carry an optional `failed: true`; `/site-admin usage` day lines and the window total show `(N failed)`, and `/site info` appends `· N failed` to the thread's usage line when any did.

- Fixed the publish type-check gate failing flash-model game builds on four runtime-safe code patterns (first seen as `ERR-MTERLZJ8-C827`, an `initial-2d-game-build` that failed both the check and its repair round-trip): legacy vendor-prefix fallbacks like `window.AudioContext || window.webkitAudioContext` (TS2551/TS2339 — tsc's DOM lib doesn't carry Safari-era APIs, and the same lookups cover window globals defined by other scripts), string-literal state machines (TS2367 "no overlap" comparisons and TS2322 assignments whose target type is a string literal), and surplus call arguments (TS2554 "Expected 0 arguments, but got 1", including the `1-2`/`at most N` range forms — JavaScript ignores extra arguments at runtime, and generated code routinely passes an event or status object to a helper declared without parameters). Half of the literal-pinning class was harness-induced: `NET_STATUS` in `threadsite-net.js` is an `Object.freeze` literal map, and under `--checkJs` frozen properties keep non-widening literal types — so the idiomatic `let status = NET_STATUS.CONNECTING; status = NET_STATUS.RECONNECTING;` pinned `status` to the singleton `"connecting"` and failed on every reassignment or comparison, exactly matching the alert's `"connecting"`/`"reconnecting"` errors. `NET_STATUS` and the generated `net-config.js`'s `NET_CONFIG` (same freeze pattern) are now JSDoc-typed to plain `string`/`number` so authored copies widen normally, and the gate drops the three diagnostic classes above so game-*owned* frozen constant maps (which flash models copy from that pattern) pass too. Trade-offs: dead-branch comparisons and surplus-argument calls now pass (heuristics, never browser-fatal — a function that silently ignores an argument is ordinary JavaScript), and property typos on `window` pass like they already did on other base-typed DOM receivers; the too-few-arguments direction (the one that surfaces as `undefined` inside the callee), undefined variables, non-literal type mismatches, misspelled vendored exports, and the element-ID check all still fail the turn. The AGENTS.md contract documents the new lenience so the agent's single repair round-trip is never spent "fixing" these. Verified with a fixture reproducing all four classes (fails before, passes after), a control fixture confirming every still-enforced class keeps failing, and a real generated site passing unchanged.

- Fixed returning visitors being served stale sites for hours after a publish. The cache-busting rewrite only versioned asset references in HTML (`js/main.js?v=…`), but a page loads most of a game through ES module import specifiers *inside* the JS files (`main.js` → `import "./game.js"` → `import "./bigfoot.js"`), which carried no version — so a browser (or CDN) that had cached those unversioned URLs kept serving the old module graph until the cache entry expired (Cloudflare's default browser TTL is four hours), and the newly published files were never even requested. The rewrite now also versions relative `.js`/`.mjs`/`.css` import/export specifiers (`from`, `import`, dynamic `import()`) inside published JS, resolving each against its own file. All version hashes are computed from the original file bytes before any rewriting starts, so a file's version never depends on rewrite order or on its own rewritten content, and unchanged files keep identical URLs. References the rewriter cannot resolve (dangling hrefs, a `./x.js` mentioned in a comment) now pass through unversioned instead of failing the publish. The example sites vhost now distinguishes versioned URLs (`?v=` → immutable, cache a year) from unversioned asset requests (`no-cache` → immediate ETag revalidation) so anything the rewrite misses still picks up a republish on the next load, and the README documents setting a fronting CDN's Browser Cache TTL (e.g. Cloudflare's) to "Respect Existing Headers" instead of a fixed four-hour default. Existing sites pick the fix up on their next publish or `/site republish`; a visitor with the old page already cached needs one hard refresh after that.

- Fixed restart recovery silently abandoning turns that were interrupted mid-step instead of continuing them. The boot-time decision between "the turn already finished on the agent side while the bot was down" (commit and publish only) and "the turn is incomplete" (send the continue prompt) tested whether *any* assistant message in the session had completed after the turn started — but an agentic turn's intermediate tool-call steps each complete with timestamps seconds into the turn, so a restart that landed after the agent's first step looked "finished": recovery committed the partial edits (typically a tiny skeleton diff) and published, never asking the session to continue — visible only as a suspiciously fast ⏱️ duration and a one-file commit on the ♻️ message. The check now requires the session's newest message to be that turn's terminal assistant response, using the same predicate the in-flight reconciliation path already applies (`finish` present and not `tool-calls`, no error, main agent, completed after the turn started), so a mid-step interruption gets the continue prompt as intended. An errored final message counts as not-completed, so recovery asks the session to continue rather than committing the failure, and unreadable history still falls back to not-completed. The ♻️ final message now also carries the agent's summary (or the "already finished on the agent side" note for the commit-only path) via the same budgeted formatter as ✅ messages, so the thread shows which path ran instead of only stats and links.
- `/site info` now shows the thread's own lifetime usage from the token/cost ledger: model-turn count, billed input with cached share, output tokens, and which models served the thread (top three by tokens, with a `+N more` overflow). Token counts are visible to everyone in the thread; the lifetime spend figure is appended only for admins (Manage Server or `DISCORD_ADMIN_USER_IDS`), keeping cost data under the same admin-only policy as `/site-admin usage` and the turn subtext. Threads with no ledgered turns yet show "Usage: none recorded yet".

# V2.3.1

- New `/site-admin usage [days]` command for tokenomics: per-day totals (turns, billed input with cached share, output, USD cost) covering today and further back (default 7, range 1–30), a window total, and a per-model breakdown (turns, tokens, cost). Usage is persisted to an append-only JSONL ledger (`USAGE_LOG_FILE`, default `/data/usage-log.jsonl`) as one line per completed turn — initial builds, mutations, validation-repair passes, restart recovery — plus each AI thread-title prompt, so history accumulates across restarts without growing bot state. Days are bucketed in the bot's local timezone, empty days are skipped, and reports that would exceed Discord's 2000-character ephemeral limit elide the oldest days with a note. `TurnUsage` now carries the turn's provider-reported cost and a per-model token/cost breakdown, attributed per step from assistant-message events including subagent child sessions (an `unknown` bucket catches steps whose model was never observed); repair folds merge per-model buckets, and cost stays admin-only — the public ✅/♻️ turn subtext continues to show tokens/context but never spend. Caveats: failed turns are not ledgered (partial usage is not observable once the prompt throws), pre-turn compaction prompts are not observable to the harness, and cost shows $0 with an explanatory footnote when the provider's pricing is unknown to the agent service.
- The bot now manages per-thread session context lifecycle automatically, before every non-initial turn: a thread whose last turn ran more than `SESSION_IDLE_RESET_MS` ago (default 2 hours, `0` disables) starts a **fresh agent session** on its next message — by then the provider prompt cache is cold and the old conversation is stale turn-by-turn detail, while the workspace, git history, and `PROJECT_NOTES.md` keep everything durable — and a session whose previous turn ended with its context window more than `SESSION_CONTEXT_COMPACT_THRESHOLD` full (default 50%, `0` disables) is **compacted at the turn boundary** before the next prompt, instead of paying for a near-full window or relying on a mid-turn auto-compaction. `ProjectRecord` persists `lastTurnAt` and the end-of-turn context reading to drive both rules; failed turns still count as activity, `/site reset` clears both readings, both actions are visible as 🧹 progress lines, a failed pre-turn compaction never fails the turn (OpenCode's own auto-compaction relative to `SURPLUS_CONTEXT_CAP` remains the mid-turn safety net), and restart recovery is intentionally exempt so it continues the interrupted turn in its own session.
- `/site-admin effort` now actually reaches Surplus models that support it. Three broken links were found and fixed: the generated provider config declared no model variants, so the bot's `variant` prompt field was silently dropped; even declared, OpenCode serializes variant options as a top-level `options: {reasoningEffort}` wrapper that OpenAI-compatible gateways ignore (Surplus honors only snake_case `reasoning_effort` — verified: low ≈ 36–48 reasoning tokens vs default 43–53, high 71, same prompt); and OpenCode ships a bundled Surplus provider definition whose options override project config under the same provider id. The fix rides the bundled provider instead of fighting it: new `opencode/surplus-adapter.mjs` keeps catalog discovery, the context cap, and limits, adds `minimal`/`low`/`medium`/`high`/`xhigh`/`max` variants for every catalog model advertising `reasoning_effort`, mirrors the bundled 50-minute timeout, and runs a loopback translating proxy (`SURPLUS_PROXY_PORT`, default 18098, `0` disables) that rewrites the wrapper into `reasoning_effort` before requests leave the container. Verified end-to-end in the built Docker image: a `variant: "low"` turn logs one translation and completes; a plain turn logs none. Caveat for local testing: a desktop OpenCode install with a `surplus` auth-store entry overrides the generated options, so the proxy takes effect in the container (or any host without that auth entry).

- The publish type-check gate no longer type-checks vendored software. A game vendoring a library under `site/assets/` (e.g. `three.module.min.js` via `asset_download`) failed the turn with hundreds of bogus diagnostics from inside the minified bundle (TS2339/TS2351 on minified internals — ~680 lines for three 0.160) plus knock-on errors at authored call sites whose types were misinferred from the minified source. The gate now runs tsc against a temp mirror of the site's scripts in which every vendored `.js`/`.mjs` under `assets/` is replaced by a generated `.d.ts` stub declaring the module's real export names as `any`: authored namespace/named/default imports resolve cleanly (a misspelled export name still fails with a "did you mean" suggestion, which the agent can act on), while the vendored implementation never enters the tsc program — the same trust model the gate already used for bare CDN imports. Vendored files are still covered by the `node --check` syntax pass over the real tree, so a truncated download still fails the turn. The harness-owned `js/threadsite-net.js` client keeps its real types for authored call sites; its own internal diagnostics stay filtered.
- Strict default-import semantics: `--allowSyntheticDefaultImports false` is now passed explicitly (tsc computes it on for this module/resolution combo). `import lib from "…/three.module.min.js"` — a browser-fatal mistake on a module with no default export — now fails the gate instead of passing silently. A vendored module that genuinely has a default export declares it in the stub and default-imports normally.
- Diagnostic filtering is now block-based: tsc diagnostics that span multiple lines (e.g. the TS2351 `Type 'Function' has no construct signatures.` detail line) previously survived line-by-line filtering as orphaned text and could fail a turn on their own; detail lines now drop together with their filtered header. On Windows hosts, CRLF output no longer breaks the end-of-line anchors. Type-check error paths are rewritten site-relative (`js/main.js(3,10)`, no temp-mirror prefixes), and the element-ID mismatch lines no longer print a doubled `js/js/…` prefix.
- Trade-off: member/property typos on values imported from vendored modules pass the gate (the imports are `any`), exactly as they already did for bare CDN imports — the real export-name list is still enforced. Extensionless imports of a vendored `.mjs` (`import … from "../assets/lib/utils"` targeting `utils.mjs`) now fail with TS2307; browsers cannot resolve that specifier either (no extension resolution in ESM), so the old pass was itself a gate blind spot — use the full filename.
- The `AGENTS.md` contract now tells the agent that vendored files under `site/assets/` are never type-checked, imports from them are treated as `any`, and named imports must use the library's real export names.

- `asset_download` now presents a realistic browser User-Agent (with the fetcher token appended) instead of a custom one: some asset CDNs and hotlink protections reject non-browser clients outright, and a blocked download tool pushes the agent toward raw `node -e` fetches that skip the size cap and `ASSET_SOURCES.json` provenance. None of the tool's real guards (SSRF/private-IP DNS checks, HTTPS-only, size caps, provenance recording) depend on the UA string. (Diagnosis of the incident that prompted this: the repeated `static.poly.pizza` 403s were S3 `AccessDenied` for guessed object keys — poly.pizza's page slug is not its S3 resource id, and the real key downloads fine — not UA filtering. No site-specific URL resolution was added.) The shell allowlist now also permits `echo` (a lone `echo "---"` inside an otherwise-allowed compound command previously rejected the whole call) plus `unzip`/`tar`, with `unzip` installed into the opencode image (not in bookworm-slim), making ZIP-distributed asset packs (Kenney, Quaternius) a supported flow: the download itself still goes through the guarded tool and only extraction is local. `AGENTS.md` and the `sitebuilder` prompt document the archive workflow (download into `site/assets/`, extract, remove the archive — it counts against the site size budget).

# V2.3

- The publish type-check gate no longer fails turns for TS2339 member accesses on DOM base-typed receivers. `querySelector`/`querySelectorAll` results, `event.target`, and Node-family traversal are typed `Element`/`EventTarget`/`Node`/…, so idiomatic accesses like `el.dataset.state` or `inputEl.value` — runtime-safe on whatever element the selector actually matches — failed the check, and flash-tier models kept writing them even after the repair round-trip. Those diagnostics are now dropped like the other lenience filters (bare-import TS2307, vendored client). Trade-off: property typos on those same receivers pass the gate too; the element-ID check still guards the missing-element bug class. The `AGENTS.md` contract now tells the agent no narrowing/casts are needed for base-typed DOM lookups.
- Restart recovery is now visible and bounded instead of silent: when the bot resumes a turn that was in flight across a restart, it resumes editing the turn's own live status message (the record now persists its message id) with the same rolling progress as normal turns — including model narration — and only posts a fresh ♻️ message when the original was deleted. The recovery prompt is bounded by `OPENCODE_RECONCILE_TIMEOUT_MS`. On timeout the orphaned agent turn is aborted best-effort, the thread's queue frees for the next message, and the failure is reported in the thread. Previously recovery ran silently, the interrupted turn's status message froze forever mid-progress, and every new message queued behind recovery showed "Waiting for the project queue"; a wedged agent turn could hold the thread's queue forever.
- Fixed a process-fatal unhandled promise rejection in the per-thread work queue: any queued job that failed without its own catch (busy-session refusals on `/site reset|compact|revert|republish`, deleting a thread mid-turn, the rollback button) crashed the whole bot, which Docker then restarted — taking every in-flight thread turn down with it. Queue failures now stay contained to their thread, and stray `unhandledRejection`/`uncaughtException` events are logged instead of terminating the process.
- Final turn messages (✅ and ♻️) now carry a usage subtext — `⏱️ <duration> · 🧠 context <size> / <limit> · in <tokens> (<cached> cached) · out <tokens> tok · compacted N×` — covering the wall time of the whole turn, cumulative billed tokens, and the context size the model ended on; validation-repair passes are folded in. Turns whose usage could not be observed (recovered after already finishing while the bot was down) show just the duration.
- The git link in final messages now uses angle brackets (`[git](<…>)`) so Discord never renders a link embed for the Forgejo repository.
- Live-progress compaction counts are per turn now; they previously showed the session-lifetime total.

- Removed public references to the underlying agent platform from everything players and server members see: Discord command descriptions and replies, live progress lines, `/site-admin status` output, generated project READMEs, and the `AGENTS.md` profiles now say "the agent"/"agent service" instead of naming the tool. Internal identifiers (env vars, Docker service name, file paths, logs) are unchanged.

- AI thread titles are now adopted end-to-end: when the `titler` agent's title lands after a successful first build, the harness renames the Forgejo repository and the published site directory to match (keeping the unique thread-id suffix), repoints the workspace git remote, rewrites the README, removes the old published directory, and refreshes the public index. Previously only the Discord thread name changed while repo/slug names stayed on the original prompt slug.
- Title adoption is now failure-proof and visible instead of silent: the rename sequence retries once, every step is idempotent (a Forgejo 404 on the old repo name counts as success when the new name already exists), the repo description is rewritten to the title, the restamped README/net-config are committed and pushed immediately (`Rename project to …`) so the Forgejo page shows the new name right away, a failure posts a ⚠️ line in the thread instead of only a log entry, and bot-created threads no longer produce double-prefixed `site-site-…` repo names when the title never lands.

- Multiplayer UX: protocol v2 adds **peer-owned state** as the recommended sync model for casual games. Each player simulates their own entity locally and broadcasts it (`pstate` frames, 10–20 Hz) — controls no longer route through the host, so input latency is exactly local play and losing the host never affects anyone's controls. Interactions become events the target applies to itself; shared-world entities get a single owner. The relay retains each peer's newest player state and hands them to late joiners in `welcome`. Host-authoritative simulation remains documented as the option for shared-physics/competitive games.

- Redesigned final turn messages: the ✅/❌ status line with project name, commit, and file count comes first; the agent's summary follows with its meta opener ("Implemented a complete … game in site/") stripped; and the play/open + source links moved to the bottom with the Forgejo URL in angle brackets so it never embeds. The "V2.1 game-specific AGENTS.md" boilerplate line is gone, and the `sitebuilder` prompt now asks for summaries that start with substance instead of restating the deliverable.

- Richer live progress: the status message keeps a short rolling tail of the last few activity steps instead of only the newest one, the narration summary line can run to ~180 characters, the per-turn token counter is labeled `this turn … tok` (tokens generated for the current Discord request, not a turn count), and final turn messages keep up to ~1600 characters of the agent's summary instead of 700.

- Real git history: commit subjects are the actual Discord request (single line, 72 chars) instead of repeated "Update game from Discord". The Discord user who sent the request is the commit author (display name + `@users.noreply.discord.com` noreply email), and the bot is the committer with a `Co-authored-by:` trailer (`COMMIT_BOT_NAME`, default SiroroBot; `COMMIT_BOT_EMAIL` defaults to `FORGEJO_BOT_EMAIL` so Forgejo links the service account avatar).

- Multiplayer games: a single shared **multi-tenant relay** (`gameserver` service) hosts every generated game. Tenancy is the game id (the site slug) plus per-game room codes, so any number of games run on one container with no per-game instances or provisioning.
- **ThreadSite Multiplayer Protocol v1**: a small documented JSON-over-WebSocket protocol (join/welcome, peer join/leave with server-side host migration, relayed events, room snapshots with late-joiner handoff, state requests, ping/pong) implemented by the relay and by a vendored zero-dependency browser client.
- The harness now provisions every game project with `site/js/threadsite-net.js` (the protocol client) and `site/js/net-config.js` (that game's tenant id + relay URL), and re-checks both every turn in case the agent removed them.
- Game `AGENTS.md` profiles gained a **multiplayer-first** section: every game is designed as a multiplayer game first, with solo play as the same game with one player (plus optional bots). It documents the full wire protocol, the recommended host-authoritative sync model (snapshots at 8–15 Hz, input intents with sequence numbers, interpolation, host-migration recovery), the lighter last-writer-wins alternative, untrusted-input validation, and the required lobby/room-code/offline-fallback UX.
- The first-turn game instruction and the OpenCode `sitebuilder` agent prompt both push multiplayer-first and forbid any other runtime network endpoint or self-written server code.
- `/site-admin status` now reports relay health (games/rooms/players) from the new `/health` and `/stats` endpoints.
- Relay hardening: per-connection token-bucket rate limiting, frame size caps via WebSocket `maxPayload`, per-room peer caps, per-game room caps, join timeouts, dead-peer heartbeat, empty-room garbage collection with TTL, and an optional `GAMESERVER_ALLOWED_ORIGINS` origin allowlist.
- Production wiring example for host Apache (`apache/gameserver-vhost.conf.example`) proxying `wss://…/ws`; the bundled/local default is `ws://localhost:8090/ws`.
- Room state is in-memory only: relay restarts clear rooms, and games are expected to recover through reconnect + snapshot resync or the solo fallback.

# V2.2

- Live progress now shows information streamed from OpenCode itself: the current todo item with plan progress, a one-line public summary of the model's narration (`💭 …`), and a small subtext line with session context usage (`🧠 context 62.4k / 100k · turn 8.1k · compacted 2×`). The status message stays minimal: only the current activity line is shown and older activity is dropped.
- AI-generated thread titles: when ThreadSite creates a new thread without an explicit `name`, a tiny `titler` agent session generates a concise title in parallel with the first build, and the thread is renamed after the build succeeds. Failures keep the slug name silently.
- `/site compact` triggers OpenCode's on-demand session compaction using the session's last model (or the configured global model).
- `/site revert` undoes the prior turn end-to-end: OpenCode conversation revert, `git reset --hard HEAD~1`, force-push to Forgejo, and republication of the previous site. Failed-but-unpublished turns only have their conversation reverted; reverting below the initial commit is refused.
- Surplus models are capped at a `SURPLUS_CONTEXT_CAP` artificial context window (default 100000 tokens, `0` disables). Auto-compaction fires relative to this ceiling, keeping long threads compact before provider windows fill.
- `ProjectRecord` now tracks `lastCommit` for safe reverts.

# V2.1.1

- Removed `asset_download` extension and MIME-type allowlists. The guarded downloader can now save any public HTTP(S) response beneath `site/assets/`, including JavaScript vendor modules, JSON/data, shaders, uncommon model formats, archives, and extensionless files.
- Kept URL/SSRF protection, redirect limits, destination traversal protection, download timeout, and `ASSET_MAX_BYTES`.
- Changed publication validation from a narrow static-extension allowlist to a small server-executable denylist. Unknown/arbitrary static file extensions are now allowed, while obvious Apache/server executable formats such as PHP/CGI/server-side scripts remain blocked.

# ThreadSite V2.1 changes

- Transport-aware OpenCode prompt recovery: `fetch failed`/socket/DNS/timeout failures no longer automatically become provider failures.
- Pre-prompt message snapshots plus persisted-message read-repair recover an already-running/completed OpenCode turn without re-sending the prompt.
- Event stream reconnect progress is shown publicly while detailed transport diagnostics remain private.
- OpenCode `/session/status` is treated as advisory; a persisted terminal assistant message wins over stale `busy` state.
- Recovery timeout attempts an HTTP session abort; if stop cannot be confirmed, ThreadSite skips rollback rather than racing a still-running agent.
- Recursive `Error.cause` serialization is included in JSONL logs and administrator DMs.
- Warn/error Docker log records use JSON output so nested causes are visible instead of `[Object]`.
- New `OPENCODE_RECONCILE_TIMEOUT_MS` and `OPENCODE_RECONCILE_POLL_MS` settings.

# ThreadSite V2 changes

- Live Discord progress message driven by OpenCode events and harness stages.
- Public failures show only an incident reference; detailed diagnostics are written to a private JSONL log and optionally DM'd to configured error-report users.
- `/site-admin errors` is restricted to explicit private error recipients.
- Provider retry/auth/rate-limit/billing/upstream failures are surfaced with clearer logging and hints.
- Site, 2D game, and 3D game `AGENTS.md` profiles strongly encourage sensible multi-file front-end architecture.
- OpenCode web search is enabled through Exa.
- Guarded `asset_download` custom tool can save public HTTPS image/audio/video/font/3D media into `site/assets/`, blocks local/private network targets, caps file size, and records provenance.
- 2D and 3D game guidance expanded for game loops, input, responsive/mobile behavior, performance, rendering structure, media research, and asset provenance.
- Automatic OpenCode context compaction is explicit; successful compaction is shown in progress and logged.
- Surplus Intelligence is available as the `surplus` custom OpenAI-compatible provider with startup model discovery and model-limit metadata when available.
- Forgejo is bound to loopback for host reverse proxying; Virtualmin/Apache proxy example and proxy checker included.
- Forgejo bootstrap no longer defaults to reserved username `admin`; default human admin is `forgeadmin`.
