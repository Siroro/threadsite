## 2D direction

- A curated **2D skill set** is installed under `.opencode/skills/` (`game-2d`, `phaser-4`, and shared game-feel/camera/input/audio/level/performance/physics/genre skills). Load the relevant skill before building or substantially revising that subsystem.
- **Phaser 4.2.1 is the default 2D game engine**: `import * as Phaser from "phaser"` from the harness-managed `node_modules/`. Never run npm, hotlink Phaser, vendor another copy, add Vite, or create an import map. The harness bundles and type-checks the real Phaser package for you. DOM/SVG remains acceptable for card/board/UI-heavy experiences where a game engine is genuinely unnecessary.
- Prefer Phaser's existing game primitives over inventing equivalents: Scenes/lifecycle, Scale Manager, Cameras, Loader, Input, Tweens, Animations, Particles, Groups/Pools, Tilemaps, timers, and **Arcade Physics for simple 2D collision/overlap**. Use Matter only when rigid-body constraints/rotation are genuinely core mechanics.
- For action games, use Arcade Physics for player↔world collision and simple interactive bodies, but **do not give thousands of swarm enemies/projectiles mutually-colliding physics bodies**. Use lightweight custom movement plus spatial hashing/grid queries for high-count actors and keep Phaser for rendering/lifecycle.
- Build map art and collision from the **same authored map definition** (tile collision properties or explicit world-space collider data). Never eyeball invisible colliders separately from artwork. During development provide a toggleable physics/collider debug overlay so alignment can be verified.
- Separate shared simulation state from presentation. Phaser Scene `update()` / RAF is not a multiplayer authority clock: shared timers use `net.serverNow()` and host migration/resync follows AGENTS.md.
- Build game feel without losing clarity: tweens, particles, trails, restrained camera shake, squash/stretch, hit flash, sound layering. Pool/cap hot objects; touch controls must not cover the play area; backgrounds, UI, transitions and typography deserve authorship.
- **The photograph is the first frame.** The harness photographs the game as it loads, before anyone plays, so the opening frame must show the playfield as it is meant to be seen — the player in the scene, the world drawn, the camera framed on the action. Never a menu, a loading screen, an empty map or a HUD floating over nothing.
